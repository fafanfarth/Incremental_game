# 11. Phase 0 実測結果と、設計書への反映

ステージ1「独房棟」の経済をシミュレータで回した結果と、
そこから必要になった設計変更の記録。

- 実装: [`prototype/`](../prototype/README.md)
- 再現: `python3 prototype/run_balance.py`

## 11.1 合格判定

docs/07 Phase 0 の合格条件は **手動 25分±5 / 放置のみ 60分±15**。

```
ステージ1「独房棟」バランス検証  （8 試行 / 固定60Hz / seed 1..8）

プロファイル        タップ/秒      中央値       最短       最長          生涯獲得  判定
------------------------------------------------------------------------
手動              4.0    23.9分    23.5分    24.6分     4,862,061  合格
併用              1.2    39.9分    37.7分    41.1分     4,878,895  ―
放置のみ            0.1    66.3分    61.7分    69.6分     4,871,808  合格
```

**合格**。ただし到達までに、設計書の数値のうち 4箇所を直す必要があった（11.2）。

## 11.2 設計書の誤りとして見つかったもの

### ① 壁の層報酬が発散していた（致命的）

docs/03 3.1 の式は次のとおりだった。

```
層 n の必要ダメージ = 10 × 1.35^n
層 n の突破報酬     = 50 × 1.60^n
```

「層を進めるほど1層あたりの旨味が増える」という意図は正しいが、
比 `1.60 / 1.35 = 1.185` は **1層ごとに +18.5% の複利**であり、30層で ×164 になる。

| 層 | 必要ダメージ | 層報酬 | 報酬 ÷ その層のタップ収入 |
|---|---|---|---|
| 0 | 10 | 50 | ×5.0 |
| 10 | 201 | 5,498 | ×27.3 |
| 20 | 4,043 | 604,463 | ×149.5 |
| 30 | 81,285 | 66,461,400 | ×817.6 |

この式のまま回すと **ステージ1が 82秒でクリアできた**。

**修正**: 層報酬を `5 × 1.37^n` に変更。比 `1.37/1.35 = 1.015` ＝ 1層ごとに +1.5%。
「進むほど旨味が増える」感触は残しつつ、30層で ×1.6 に収まる。

### ② 「1回きりの固定報酬」に全体倍率が乗っていた

docs/03 3.1 の隠し物は「1回きりの固定報酬」と書かれているが、
実装の素直な読みでは全体倍率とブーストが乗る。すると層20の1個で **45万** が入り、
そこでスキルを4つ同時に買えてしまい、成長曲線がその瞬間に折れる。

**修正**: 隠し物は倍率を一切乗せない固定額とする。倍率は `hidden_item_reward_mult`
（D2 隠し場所 / D6 壁の向こう）だけが乗る。報酬も層報酬の ×5 → ×3 に下げた。

### ③ A系統の「全獲得量 ×N」が自動収入にも乗って崩壊していた（最重要）

これが最大の問題だった。A4/A5/A6（×2 / ×3 / ×5）と C5 房のボス（×3）、
さらに消灯時間（×4）がすべて自動収入に乗ると、**子分の回収時間が 1/360 になる**。

| 子分 | 素の回収時間 | 倍率が乗った後 |
|---|---|---|
| 新入り | 75秒 | **0.8秒** |
| 古株 | 229秒 | **2.5秒** |
| 掃除夫 | 750秒 | **8.3秒** |
| 看守補佐 | 2,364秒 | **26.3秒** |

回収8秒の投資は実質的に無限増殖であり、自動収入が 136,000/秒（設計想定の16倍）に達した。

**修正**: **A系統は手動（タップ・層報酬）にのみ効く。自動収入は C系統でのみ伸びる。**

この変更には副次的な利点がある。修正前の A系統は
「手動にも自動にも効く」ため **他の3系統に対して常に優位** だった。
分離によって A＝手動を鍛える枝、C＝自動を鍛える枝という役割分担が生まれ、
04章 4.1 の系統定義が実態と一致するようになった。

> **docs/04 の全ステージに適用すべき原則**:
> 「全獲得量 ×N」と書かれた効果は、**手動由来の獲得にのみ適用する**。
> 自動収入に倍率を乗せるのは、その系統専用のノードだけに限る。

### ④ 子分に上限がなかった

docs/04 の S1-C2「仲間を増やす」は「子分の購入上限 +10」とあり、
設計には上限の概念があったが、数値が定義されていなかった。
上限なしで回すと掃除夫を22体買い、自動収入が制御不能になる。

**修正**: 各ティアに定員を設定。新入り30 / 古株20 / 掃除夫12 / 看守補佐40。
看守補佐は1体 260万で目標額（100万）より高く、**クリア後にだけ意味を持つ**
という docs/03 の記述どおりの位置づけになった。

## 11.3 コスト階梯の再調整

上の4点を直した時点で手動クリアは **17.3分**。合格条件（20〜30分）に届かない。
docs/07 7.5-3 が想定していたとおり、コスト階梯の再調整を行った。

| 段 | 旧 | 新 | 比 |
|---|---|---|---|
| T1 | 50 | **50** | ― |
| T2 | 250 | **300** | ×6.0 |
| T3 | 1,200 | **1,900** | ×6.3 |
| T4 | 6,000 | **12,000** | ×6.3 |
| T5 | 30,000 | **80,000** | ×6.7 |
| T6 | 150,000 | **520,000** | ×6.5 |
| **ツリー総額** | 750,000 | **2,457,000** | |

階梯比を ×5 から **×6.2 前後**に引き上げた。
候補を並べた実測は次のとおり（手動 10試行 / 放置 6試行）。

| 階梯 | ツリー総額 | 手動 | 放置のみ | 判定 |
|---|---|---|---|---|
| 50/250/1,200/6,000/30,000/150,000（旧） | 750,000 | 17.3分 | 52.6分 | 不合格 |
| 50/250/1,200/6,000/90,000/560,000 | 2,630,000 | 23.3分 | 60.9分 | 合格（T4→T5 が ×15 で不自然） |
| 50/300/1,800/12,000/90,000/560,000 | 2,656,600 | 24.6分 | 67.6分 | 合格 |
| **50/300/1,900/12,000/80,000/520,000** | **2,457,000** | **24.3分** | **67.6分** | **採用** |

あわせて **タップの基準値を 1 → 0.35 本** に下げた。
旧値では開始直後の収入が 6/秒 となり、docs/05 5.2 が想定する 1.7/秒 の 3.5倍だった。

## 11.4 生涯獲得額の式が間違っていた

docs/05 5.1 は次のように書いていた。

```
LIFE = GOAL + TREE = 1,000,000 + 750,000 = 1,750,000
```

**反復購入（子分）への支出が数えられていない。** 実測は次のとおり。

| 用途 | 金額 |
|---|---|
| 【賄賂】T7 | 1,000,000 |
| スキルツリー T1〜T6 | 2,457,000 |
| 子分（定員まで購入） | 約 1,400,000 |
| **生涯獲得額** | **約 4,860,000** |

子分への支出はツリーの半分以上を占める。
「反復購入の逓増コストがステージ1の正体」（docs/03 3.0）である以上、これは当然であり、
**5.1 の式に第3項を足す必要がある**。

```
LIFE = GOAL + TREE + REPEAT
```

この変更は docs/08 の脱獄章の式（生涯獲得額の平方根）にも波及する（11.6）。

## 11.5 バランス上の指摘（設計判断が必要なもの）

### 抜き打ち検査の2択が成立していない

docs/02 R-09 は「期待値はほぼ同等に設定し、『安定か、加速か』の好みの表明に留める」
としているが、実測では **「袖の下」が常に優位** だった。

| 選択 | 手動クリアの中央値 |
|---|---|
| 常に「袖の下」を選ぶ | **22.7分** |
| 常に「隠す」を選ぶ | 27.4分 |

理由は構造的なもので、調整では直らない。

- 「隠す」は **成功しても何も起きない**（損失を回避するだけ）
- 「袖の下」は所持額の5%を払って **90秒 ×2 のブースト**を得る
- インクリメンタルでは所持額（ストック）より収入（フロー）の方が価値が高いため、
  **フローを買う選択肢が常に勝つ**

**提案**: 「隠す」に成功したとき **90秒 ×1.5 のブースト**を与える。
成功すれば袖の下より得（×1.5 を無料で得る）、失敗すれば所持額 −10% で何も得られない
という、本物の博打になる。これは docs/02 R-09 の書き換えを伴うため、判断を仰ぎたい。

### 設計曲線（05章 5.2）は実測で置き換えるべき

| 時刻 | 設計曲線の累計 | 実測の累計 |
|---|---|---|
| 2分 | 200 | 743 |
| 6分 | 2,500 | 8,807 |
| 12分 | 20,000 | 146,246 |
| 20分 | 120,000 | 1,512,750 |
| 23.5分 | ― | **4,860,379（クリア）** |

設計曲線は手で書いたスケッチであり、実際のツリー構造から出てくる曲線とは形が違う。
**フェーズの区切り（P0〜P5）という考え方は有効だが、数値は実測に置き換える。**
