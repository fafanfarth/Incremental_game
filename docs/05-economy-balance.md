# 05. 経済バランス

## 5.1 基本方程式

1ステージの収支は次の 3 数値で定義される。

| 記号 | 意味 | 値 |
|---|---|---|
| `GOAL` | 賄賂に必要な所持額 | **1,000,000** |
| `TREE` | 本編ツリー総額（T1〜T6 の24ノード） | **2,457,000** |
| `REPEAT` | 反復購入（子分・機械Lv 等）への支出 | **約 1,400,000** |
| `LIFE` | クリアまでの生涯獲得額 | **約 4,860,000** |
| `LEGACY` | 継承ツリー総額（L1〜L4） | **623,000,000** |

`GOAL` は独立したイベントではなく、**ツリー T7 の【賄賂】ノードのコスト** である（R-01）。

```
LIFE = GOAL + TREE + REPEAT
```

初版は `LIFE = GOAL + TREE` としていたが、**反復購入への支出が数えられていなかった**。
実測では子分への支出が 140万（ツリーの 57%）に達する。
「反復購入の逓増コストがステージ1の正体」（03章 3.0）である以上これは当然であり、
第3項は必須である（11章 11.4）。

T6 ノード（520,000 × 4）は全買いを前提にしない。
T6 を 0個買う最速ルートでも、4個全買いでも **どちらでもクリアできる** ことが
バランスの合格ラインである。

`LEGACY` はクリア後の長期目標で、`LIFE` の **約 128倍**。
これは「クリアで終わり」ではなく「クリアからが後半」という時間配分を意味する
（5.9）。

## 5.2 成長曲線

標準プレイヤー（手動 4タップ/秒）における1ステージの進行モデル。
以下は **ステージ1の実測値**（`prototype/run_balance.py --curve`）であり、
他のステージもこの形に合わせる。

| フェーズ | 名称 | 経過時間 | この時点の累計獲得 | プレイヤーの行動 |
|---|---|---|---|---|
| P0 | 徒手空拳 | 0〜3分 | 1,500 | 手動のみ。T1 の4ノードを揃える |
| P1 | 最初の他人 | 3〜9分 | 22,000 | 自動収入が動き出す。T2〜T3 |
| P2 | 自動化到達 | 9〜14分 | 230,000 | **T3（オート系）を購入**。放置が成立 |
| P3 | 倍率の発見 | 14〜18分 | 1,100,000 | T5。数字の単位が変わる |
| P4 | 複利 | 18〜21分 | 3,150,000 | 自動と手動が噛み合う |
| P5 | 爆発 | 21〜24分 | 4,860,000 | T6 を取捨選択し、GOAL へ到達 |

- 最終 CPS はおよそ **4,500〜7,000/秒**（消灯時間とブーストで振れる）
- 放置のみのプレイヤーは **66分**（手動の 2.8倍）。必ず到達する
- 初版の 5.2 は手で書いたスケッチで、実測とは形が違っていた（11章 11.5）。
  **フェーズという考え方は有効だが、数値は必ず実測で置き換える**

## 5.4 コスト式

### スキルノード
段階固定（04章のコスト階梯）。**同一ノードの再購入は無し**（1回買い切り）。

### 反復購入型アイテム（子分・機械Lv・基礎搬出量等）
```
cost(n) = base × 1.15^n     ( n = 既購入数 )
```
- `1.15` は Cookie Clicker 系の標準値。購入間隔が体感的に心地よい
- 一括購入ボタン（×1 / ×10 / ×最大）を必ず用意する（NFR-04）

### 倍率の適用範囲（最重要）

**「全獲得量 ×N」は手動由来の獲得にのみ適用する。自動収入には乗せない。**
自動収入を伸ばすのは、その系統専用のノード（S1-C5 など）だけ。

これを破ると反復購入の回収時間が数百分の1に潰れ、経済が崩壊する。
Phase 0 で実際に崩壊させて確認した（11章 11.2-③）。

### 収入の合成規則
```
収入 = 基礎値
     × (1 + Σ 加算系ボーナス)      ← 同種のボーナスは加算
     × Π 乗算系ボーナス            ← 種類の違うボーナスは乗算
     × 一時ブースト
     × 継承ボーナス（他の棟の L ノード由来）
（手動と自動で別々に計算し、最後に合算する）
```
- 加算と乗算を明確に分けて表示する。プレイヤーが「次にどれを買うと伸びるか」を
  自力で計算できることがインクリメンタルの根幹

## 5.5 オフライン進行

**解放済みの全棟が同時に蓄積する**（R-08）。棟ごとに独立して計算し、合算表示する。

```
棟 i のオフライン獲得 = CPS_i × min(経過秒, 上限秒) × 効率
効率   = 0.60（S2-L1 で 0.75）
上限秒 = 28,800（8時間）+ S2-L1 の +7,200 + 広告延長
```
- 手動由来の収入（タップ・ミニゲーム）は **一切含まない**
- 未表示の棟は毎フレーム演算せず、`CPS × 経過秒` の一括加算で処理する（NFR-21）
- 広告視聴で「留守中の稼ぎ ×2」を 1日3回まで（任意機能）
- 復帰ダイアログには **経過時間 / 獲得額 / 現在CPS** の3つのみを表示する

## 5.6 密輸ルート（棟をまたぐ唯一の流入）

L4 ノードで開通する、通貨非互換の唯一の例外（R-12）。

```
流入額 = Σ ( 開通済みの棟 i の CPS_i × 流入率 × レート補正(i → 現在の棟) )
流入率 = 5%（S5-L1 で 10%、永久スキル P-C3「使い走り」で最大 +10%）
レート補正 = 現在の棟の基準CPS ÷ 棟 i の基準CPS
```

**レート補正が必須**である理由: 棟ごとに数値のスケールが違うため、
補正なしでは「棟1の5%」が棟5では誤差に、逆方向では壊れた額になる。
各棟の「クリア時点の標準 CPS（約 5,000/秒）」を基準値として正規化する。

| 開通数 | 現在の棟の CPS に対する上乗せ | 体感 |
|---|---|---|
| 1本 | +5% | ほぼ気づかない |
| 3本 | +15% | 放置効率がはっきり変わる |
| 4本（S5-L1 込み） | +40% | 別の棟を遊ぶことが常に得になる |
| 5本 + 永久スキル | +60% | 5棟が1つの経済として回る |

**上限**: 密輸による流入の合計は、現在の棟の自前 CPS を超えない（100% でキャップ）。
「前の棟を放置しておけば今の棟を遊ばなくていい」状態を防ぐため。

## 5.7 乱数の扱い

| ルール | 内容 |
|---|---|
| 疑似乱数の分布保証 | 「5%で大当たり」は **20回以内に必ず1回** 出る補正付き（pity system） |
| 連敗の緩和 | ステージ3のサイコロは 5連敗で次回の期待値を +50%（表示はしない） |
| リプレイ性 | 乱数シードは端末ローカル。セーブのロード＆リトライによる粘りは防がない（シングルプレイのため） |
| 表示の誠実さ | 表示している確率と内部確率を一致させる（pity は「下振れ救済」方向にのみ働く） |

## 5.8 数値の表示規則

| 範囲 | 表示 |
|---|---|
| 〜9,999 | `8,240` |
| 10,000〜99,999,999 | `1.2万` / `34.5万` / `1,000万` |
| 100,000,000〜 | `1.2億`（継承ツリー終盤で到達する） |
| 秒間収入 | `+1,240 /秒` |

- **目標額は常に `100万` と表記**（`1,000,000` と併記しない）。「100万」がゲーム全体の合言葉
- 所持額は画面上部に固定表示し、GOAL に対する **プログレスバー** を常に添える

## 5.9 クリア後の経済（継承ツリーへの道）

クリア時点の CPS は約 5,000/秒。ここから継承ツリー最深部（5億）までを、
**反復購入型アイテムの無限購入**（`cost(n) = base × 1.15^n`）で繋ぐ。

| 目標 | コスト | 必要 CPS の目安 | 到達までの目安 | 主な手段 |
|---|---|---|---|---|
| L1 | 300万 | 5,000/秒 | クリア後 10分（放置可） | クリア時のまま |
| L2 | 2,000万 | 20,000/秒 | クリア後 40分 | 第4ティアのアイテムを揃える |
| L3 | 1億 | 100,000/秒 | クリア後 3時間 | 他の棟の L ノードが効き始める |
| L4 | 5億 | 500,000/秒 | クリア後 10時間 | 密輸ルート＋全棟の相互強化 |

**重要な性質**: L ノードは「その棟を強化しない」ため、
L3 を買ってもその棟の CPS は上がらない。CPS を伸ばすのは
**反復購入と、他の4棟から流れてくる継承ボーナス**である。
したがって 5棟を均等に育てるほど全体が加速する ――
これが終盤の「5棟が1つの経済になる」感覚の正体になる。

### クリア後に遊ぶ理由の設計

| 理由 | 仕組み |
|---|---|
| 明確な次の目標がある | 継承ツリー L1〜L4 が常に「あと◯◯で買える」と表示される |
| 効果が別の場所に出る | L ノードの効果は今プレイ中の棟に出る。**ご褒美が別の画面で起きる** |
| 放置が無駄にならない | 全棟が並行して貯まる（R-06） |
| 記録の更新 | 最深層、最高ランク、1分間最高産出などの自己ベスト |
| 密輸ルート | 開通するほど「どの棟を遊んでも全体が伸びる」状態に近づく |

## 5.10 バランス調整の原則

1. **手動 > 自動** を常に維持（手動は自動の 3〜5倍）。放置は「進むが最速ではない」
2. **どのスキルを買っても前進する**。罠ノード（買うと損する）は作らない
3. **上限を作らない**。GOAL 到達後も数値は伸び続ける（実績・記録のため）
4. **待ち時間の最大値は 90秒**。これを超える待機を強制するギミックは作らない
5. **1ステージ 40分**。これを大きく超える場合はステージ側の数値ではなく
   **フェーズ構成** を見直す（フェーズが多すぎる＝ギミックの入れすぎ）
6. **継承ノードの効果は必ず「別の棟」に出す**。現在の棟に効く継承ノードを作ると、
   棟を往復する動機が消え、この仕組み全体が死ぬ
7. **密輸ルートの流入は自前 CPS を超えさせない**。超えると現在の棟を遊ぶ意味が消える
