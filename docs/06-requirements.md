# 06. 要件定義（機能・非機能）

## 6.1 機能要件（FR）

### コア進行

| ID | 要件 | 優先度 |
|---|---|---|
| FR-01 | プレイヤーは 5つのステージを順に進行し、各ステージでそのステージ通貨を 1,000,000 所持することでクリアできる | 必須 |
| FR-02 | 各ステージは固有のミニゲーム・通貨・スキルツリーを持ち、それらはステージ間で共有されない | 必須 |
| FR-03 | 100万到達時に「看守を呼ぶ」操作が可能になり、実行すると所持額が 0 になり次ステージへ遷移する | 必須 |
| FR-04 | クリア済みステージは恒久的な「人脈ボーナス」を付与する | 必須 |
| FR-05 | ステージ5クリアでエンディングが再生され、NG+ が解放される | 必須 |
| FR-06 | ゲームオーバー・進行不能状態は発生しない | 必須 |

### 稼ぎとミニゲーム

| ID | 要件 | 優先度 |
|---|---|---|
| FR-10 | 各ステージに手動操作で通貨を得る手段が存在する | 必須 |
| FR-11 | 各ステージに最低1つの自動化スキルが存在し、プレイ時間の 25〜35% 地点で到達可能である | 必須 |
| FR-12 | 手動操作の効率は自動化の 3〜5倍を維持する | 必須 |
| FR-13 | 一時的な獲得量ブースト（持続 30〜90秒）を各ステージに1つ以上用意する | 推奨 |
| FR-14 | 抜き打ち検査イベントが一定間隔で発生し、プレイヤーは2択を選ぶ | 推奨 |

### スキルツリー

| ID | 要件 | 優先度 |
|---|---|---|
| FR-20 | 各ステージのツリーは 4系統 × 6段 = 24ノードで構成される | 必須 |
| FR-21 | ノードはそのステージの通貨でのみ購入でき、購入は1回限り、払い戻しは不可 | 必須 |
| FR-22 | 同一系統は上段から順にのみ解放できる。系統をまたぐ前提条件を1〜2本設ける | 必須 |
| FR-23 | 未購入ノードは効果とコストを常に閲覧でき、購入可能なものは視覚的に区別される | 必須 |
| FR-24 | ツリー画面から現在の合計倍率（加算・乗算の内訳）を確認できる | 推奨 |

### 放置・セーブ

| ID | 要件 | 優先度 |
|---|---|---|
| FR-30 | 自動化を1つ以上所持する場合、アプリ非起動中もオフライン進行が蓄積される | 必須 |
| FR-31 | オフライン進行は自動収入の 60%、上限 8時間（人脈ボーナスで最大 10時間） | 必須 |
| FR-32 | 復帰時に留守中の獲得をダイアログで提示し、受け取り操作で加算する | 必須 |
| FR-33 | セーブは自動（状態変化時および30秒ごと）で、手動セーブ操作は不要 | 必須 |
| FR-34 | 端末の時刻変更による不正な時間加算を検知し、サーバ時刻または単調増加時計で補正する | 必須 |
| FR-35 | クラウドセーブ（Game Center / Google Play Games）による端末間引き継ぎ | 推奨 |

### UI / 周辺

| ID | 要件 | 優先度 |
|---|---|---|
| FR-40 | 画面下部にタブ（ステージ / スキル / 図鑑 / 設定）を常時表示する | 必須 |
| FR-41 | 画面上部に所持額と 100万 へのプログレスバーを常時表示する | 必須 |
| FR-42 | 実績システム（50件以上）と、ステージごとの図鑑を持つ | 推奨 |
| FR-43 | 設定で BGM / 効果音 / 演出（パーティクル）/ 触覚フィードバック を個別に ON/OFF できる | 必須 |
| FR-44 | 日本語・英語に対応する（文字列は外部リソース化） | 推奨 |
| FR-45 | NG+ 専用のメダルツリーを持つ | 推奨 |

## 6.2 非機能要件（NFR）

### 操作性（スマホ版の肝）

| ID | 要件 |
|---|---|
| NFR-01 | **縦持ち固定・片手操作で完結する**。横持ち対応は行わない |
| NFR-02 | 全ての反復操作（タップ・スワイプ）は画面下 2/3 の領域に配置する（親指の可動域） |
| NFR-03 | タップ対象の最小サイズは 48×48 dp。誤タップで通貨を失う操作を隣接させない |
| NFR-04 | 反復購入は ×1 / ×10 / ×最大 のトグルを持ち、長押し連続購入に対応する |
| NFR-05 | 画面遷移は 200ms 以内。タブ切り替えでミニゲームの進行は止めない |
| NFR-06 | 1セッション 3分で意味のある前進（最低1ノード購入）が得られる |

### 演出・音（参考タイトルの批判点への対処）

| ID | 要件 |
|---|---|
| NFR-07 | 効果音はレイヤーごと（UI / 獲得 / 環境音 / 演出）に個別 ON/OFF 可能とする |
| NFR-08 | 同一効果音の同時再生は最大 4 に制限し、連打時は音量を逓減させる |
| NFR-09 | 高速進行時はパーティクル数を自動で間引く「省エフェクトモード」を持つ |

### 収益・公正性

| ID | 要件 |
|---|---|
| NFR-10 | 課金・広告は **時間短縮のみ** を提供し、無課金で到達不能な数値・コンテンツを作らない |
| NFR-11 | 強制的な全画面広告を出さない。広告は全てリワード型（プレイヤーが選んで見る） |
| NFR-12 | ガチャ・ルートボックス形式の課金を実装しない（ステージ3の賭博はゲーム内通貨のみ） |

### 技術・品質

| ID | 要件 |
|---|---|
| NFR-20 | 対応OS: iOS 15 以降 / Android 9（API 28）以降 |
| NFR-21 | 3年前のミドルレンジ端末で 60fps、省エフェクトモードで 30fps を下回らない |
| NFR-22 | 30分連続プレイでのバッテリー消費 10% 以下。バックグラウンド時は演算を停止しオフライン式に切り替える |
| NFR-23 | 初回ダウンロードサイズ 150MB 以下 |
| NFR-24 | 完全オフラインで遊べる（通信はクラウドセーブ・広告・実績同期のみ、いずれも任意） |
| NFR-25 | セーブデータは破損検知（チェックサム）を持ち、破損時は直近の正常バックアップへ自動復旧する |
| NFR-26 | 数値は 64bit 整数または任意精度で扱い、NG+ でのオーバーフローを起こさない |

## 6.3 技術構成（推奨）

| 領域 | 選定 | 理由 |
|---|---|---|
| エンジン | **Unity 6 (C#)** または **Godot 4** | 2Dインクリメンタルに十分。両OSへ単一コードで配信 |
| 代替案 | React + Capacitor（Web先行） | Web版で早期に数値検証を回したい場合 |
| 数値型 | `double` + 独自 BigNumber（仮数・指数） | NG+ 以降の桁あふれ対策 |
| セーブ | JSON + チェックサム、端末ローカル + クラウド | FR-33 / NFR-25 |
| 時刻 | 単調増加時計（端末稼働時間）＋ 起動時にサーバ時刻で照合 | FR-34 |
| データ定義 | スキル・コスト・文言は全て **外部データ（CSV/JSON）** に切り出す | バランス調整をコード変更なしで回すため |
| 解析 | プレイヤーのステージ別滞在時間・離脱地点・購入順を計測 | 5章のバランス検証に必須 |

## 6.4 KPI（バランス検証の指標）

| 指標 | 目標 |
|---|---|
| ステージ1 クリア率 | 80% 以上（未達ならチュートリアルか P0 が長すぎる） |
| ステージ3 クリア率 | 50% 以上（ギャンブルの分散で折れていないか） |
| 最終クリア率 | 25% 以上 |
| 1ステージあたり中央値プレイ時間 | 設計値の ±30% 以内（5.3） |
| 7日後継続率 | 25% 以上 |
| 最初の自動化到達までの中央値 | 12分以内 |
