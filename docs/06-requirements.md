# 06. 要件定義（機能・非機能）

## 6.1 機能要件（FR）

### コア進行

| ID | 要件 | 優先度 |
|---|---|---|
| FR-01 | プレイヤーは 5つのステージを順に解放し、各ステージでそのステージ通貨を 1,000,000 支払うことでクリアできる | 必須 |
| FR-02 | 各ステージは固有のミニゲーム・通貨・スキルツリーを持ち、通貨は両替できない | 必須 |
| FR-03 | クリアはスキルツリー T7 の【賄賂】ノード（1,000,000）の購入によって行われる。イベントではなくノード購入として実装する | 必須 |
| FR-04 | 【賄賂】ノードの解放条件は「4系統すべてで T4 以上を1つ以上所持」であること | 必須 |
| FR-05 | 【賄賂】購入後、その先に継承ツリー（L1〜L4）が出現する。効果は次のステージ以降にのみ及ぶ | 必須 |
| FR-06 | スキルツリーおよび各棟の残高はリセットされない。クリア後も保持される | 必須 |
| FR-07 | クリア済みの棟にはハブ画面【廊下】からいつでも戻れ、全ミニゲームを制限なく遊べる | 必須 |
| FR-08 | 解放済みの全棟の自動収入は、別の棟にいる間も並行して蓄積される | 必須 |
| FR-09 | 継承ツリー L4「密輸ルート」開通後、その棟の CPS の一定割合が現在の棟の通貨に変換されて流入する。流入合計は現在の棟の自前 CPS を超えない | 推奨 |
| FR-10 | ステージ5クリアでエンディングが再生され、**永久スキル表と記録抹消**が解放される。エンディング後も全棟がプレイ可能なまま維持される | 必須 |
| FR-11 | ゲームオーバー・進行不能状態は発生しない。反復購入型アイテムに上限を設けない | 必須 |

### 稼ぎとミニゲーム

| ID | 要件 | 優先度 |
|---|---|---|
| FR-12 | 各ステージに手動操作で通貨を得る手段が存在する | 必須 |
| FR-13 | 各ステージに最低1つの自動化スキルが存在し、プレイ時間の 25〜35% 地点で到達可能である | 必須 |
| FR-14 | 手動操作の効率は自動化の 3〜5倍を維持する | 必須 |
| FR-15 | 各ステージに「常に最大値で操作すればよい」を成立させない対抗ギミックを1つ以上持つ（03章 3.6） | 必須 |
| FR-16 | 一時的な獲得量ブースト（持続 30〜90秒）を各ステージに1つ以上用意する | 推奨 |
| FR-17 | 抜き打ち検査イベントは **未クリアの棟でのみ** 一定間隔で発生し、プレイヤーは2択を選ぶ | 推奨 |

### スキルツリー

| ID | 要件 | 優先度 |
|---|---|---|
| FR-20 | 各ステージのツリーは 本編 4系統 × 6段（24ノード）＋ T7【賄賂】＋ 継承 L1〜L4 で構成される | 必須 |
| FR-21 | 継承ノードを含め、全ノードはそのステージの通貨でのみ購入でき、購入は1回限り、払い戻しは不可 | 必須 |
| FR-22 | 同一系統は上段から順にのみ解放できる。系統をまたぐ前提条件を1〜2本設ける | 必須 |
| FR-23 | 未購入ノードは効果とコストを常に閲覧でき、購入可能なものは視覚的に区別される | 必須 |
| FR-24 | ツリー画面から現在の合計倍率（加算・乗算の内訳）を確認できる | 推奨 |

### 放置・セーブ

| ID | 要件 | 優先度 |
|---|---|---|
| FR-30 | 自動化を1つ以上所持する場合、アプリ非起動中もオフライン進行が蓄積される | 必須 |
| FR-31 | オフライン進行は棟ごとに自動収入の 60%、上限 8時間（継承ノードで最大 10時間）。解放済みの全棟が同時に蓄積する | 必須 |
| FR-32 | 復帰時に留守中の獲得を **棟ごとの内訳付きで** ダイアログ提示し、受け取り操作で加算する | 必須 |
| FR-33 | セーブは自動（状態変化時および30秒ごと）で、手動セーブ操作は不要 | 必須 |
| FR-34 | 端末の時刻変更による不正な時間加算を検知し、サーバ時刻または単調増加時計で補正する | 必須 |
| FR-35 | クラウドセーブ（Game Center / Google Play Games）による端末間引き継ぎ | 推奨 |

### UI / 周辺

| ID | 要件 | 優先度 |
|---|---|---|
| FR-40 | ハブ画面【廊下】を持ち、各棟のタイルに「残高 / CPS / 継承ツリーの進捗」を表示する | 必須 |
| FR-41 | 画面**左端のレール**にタブ（廊下 / ツリー / 図鑑 / 設定）を常時表示する | 必須 |
| FR-42 | 画面上部に所持額と、次に狙っているノード（未クリアなら 100万＝賄賂）へのプログレスバーを常時表示する | 必須 |
| FR-43 | 別の棟で継承ノードが購入可能になった際、廊下タブにバッジ通知を出す | 推奨 |
| FR-43b | 起動時に端末が縦向きの場合、回転を促す案内を表示する | 必須 |
| FR-44 | 実績システム（50件以上）と、ステージごとの図鑑・自己ベスト記録を持つ | 推奨 |
| FR-45 | 設定で BGM / 効果音 / 演出（パーティクル）/ 触覚フィードバック を個別に ON/OFF できる | 必須 |
| FR-46 | 日本語・英語に対応する（文字列は外部リソース化） | 推奨 |
| FR-47 | 周回（記録抹消）を実行でき、全ステージの通貨・本編ツリー・継承ツリーがリセットされる | 必須 |
| FR-48 | 周回で得た脱獄章で購入する**永久スキル表**（5分類×6項目＝30項目、Lv制）を持つ。周回でリセットされない | 必須 |
| FR-49 | 永久スキルはステージの対抗ギミック（03章 3.6）を無効化してはならない | 必須 |

## 6.2 非機能要件（NFR）

### 操作性（スマホ版の肝）

| ID | 要件 |
|---|---|
| NFR-01 | **横持ち固定・両手持ち**。縦持ち対応は行わない。回転ロックし、起動時に横向きを促す |
| NFR-02 | 全ての反復操作は画面の**左右それぞれ端から 28% 以内かつ下半分**に配置する（両親指の可動域）。中央は表示とドラッグ専用 |
| NFR-03 | タップ対象の最小サイズは 48×48 dp。誤タップで通貨を失う操作を隣接させない |
| NFR-03b | 主アクションボタンは**下辺の左右に対称配置**し、どちらでも同一判定とする（両親指の交互連打を許す） |
| NFR-03c | ノッチ／パンチホール／ホームインジケータを避けるセーフエリアを左右に確保する（横持ちでは左右が削られる） |
| NFR-04 | 反復購入は ×1 / ×10 / ×最大 のトグルを持ち、長押し連続購入に対応する |
| NFR-05 | 画面遷移は 200ms 以内。タブ切り替えでミニゲームの進行は止めない |
| NFR-06 | 1セッション 3分で意味のある前進（最低1ノード購入）が得られる |

### 演出・音（参考タイトルの批判点への対処）

| ID | 要件 |
|---|---|
| NFR-07 | 効果音はレイヤーごと（UI / 獲得 / 環境音 / 演出）に個別 ON/OFF 可能とする |
| NFR-08 | 同一効果音の同時再生は最大 4 に制限し、連打時は音量を逓減させる |
| NFR-09 | 高速進行時はパーティクル数を自動で間引く「省エフェクトモード」を持つ |

### 収益・公正性

| ID | 要件 |
|---|---|
| NFR-10 | 課金・広告は **時間短縮と利便性のみ** を提供する（10章 M-01） |
| NFR-11 | 強制的な全画面広告を出さない。広告は全てリワード型（10章 M-02） |
| NFR-12 | ガチャ・ルートボックス形式の課金を実装しない（10章 M-03） |
| NFR-13 | **ハードモードでは課金・広告・永久スキルの効果を全て無効化する**（10章 M-04 / 09章 FR-51） |

> 詳細な商品構成・広告枠・収益目標は [10章](10-monetization.md) を参照。
> モード別の有効/無効の切り分けは [09章 9.1](09-hard-mode.md) が正とする。

### 技術・品質

| ID | 要件 |
|---|---|
| NFR-20 | 対応OS: iOS 15 以降 / Android 9（API 28）以降 |
| NFR-21 | 3年前のミドルレンジ端末で 60fps、省エフェクトモードで 30fps を下回らない |
| NFR-21b | 表示していない棟はシミュレーションせず、`CPS × 経過秒` の一括加算で処理する。5棟同時進行でもフレーム負荷を増やさない |
| NFR-22 | 30分連続プレイでのバッテリー消費 10% 以下。バックグラウンド時は演算を停止しオフライン式に切り替える |
| NFR-23 | 初回ダウンロードサイズ 150MB 以下 |
| NFR-24 | 完全オフラインで遊べる（通信はクラウドセーブ・広告・実績同期のみ、いずれも任意） |
| NFR-25 | セーブデータは破損検知（チェックサム）を持ち、破損時は直近の正常バックアップへ自動復旧する |
| NFR-26 | 数値は 64bit 整数または任意精度で扱う。継承ツリー（5億）と周回を見込み、最低でも 1e15 までを誤差なく扱えること |

## 6.3 技術構成（推奨）

| 領域 | 選定 | 理由 |
|---|---|---|
| エンジン | **Unity 6 (C#)** または **Godot 4** | 2Dインクリメンタルに十分。両OSへ単一コードで配信 |
| 代替案 | React + Capacitor（Web先行） | Web版で早期に数値検証を回したい場合 |
| 数値型 | **固定小数点 / 整数 + 独自 BigNumber（仮数・指数）** | 周回以降の桁あふれ対策。浮動小数点を状態に持たない（NFR-31） |
| セーブ | JSON + チェックサム、端末ローカル + クラウド | FR-33 / NFR-25 |
| 時刻 | 単調増加時計（端末稼働時間）＋ 起動時にサーバ時刻で照合 | FR-34 |
| データ定義 | スキル・コスト・文言は全て **外部データ（CSV/JSON）** に切り出す | バランス調整をコード変更なしで回すため |
| 解析 | プレイヤーのステージ別滞在時間・離脱地点・購入順を計測 | 5章のバランス検証に必須 |
| シミュレータ | ゲームロジックを描画から分離し、**固定60Hz**で進める | ハードモードの残り時間がフレームレートに依存しないため（NFR-30）。オフライン進行とバランス検証の再現性にも効く |
| サーバ | レシート検証のみ（ランキングはプラットフォーム機能に委ねる） | 10章 FR-69 / 09章 9.7 |

## 6.4 KPI（バランス検証の指標）

| 指標 | 目標 |
|---|---|
| ステージ1 クリア率 | 80% 以上（未達ならチュートリアルか P0 が長すぎる） |
| ステージ3 クリア率 | 50% 以上（ギャンブルの分散で折れていないか） |
| 最終クリア率 | 25% 以上 |
| 1ステージあたり中央値プレイ時間 | 設計値の ±30% 以内（5.3） |
| 7日後継続率 | 25% 以上 |
| エンディング到達者のうち2周目に入った割合 | 40% 以上（未達なら周回の動機付けが弱い） |
| 永久スキルを1つ以上購入した割合（周回者のうち） | 90% 以上 |
| ハードモードに1回以上挑戦した割合（エンディング到達者のうち） | 35% 以上 |
| 死線 I のクリア率（挑戦者のうち） | 40〜60%（低すぎれば厳しすぎ、高すぎれば緩い） |
| 死線 I の初クリアまでの挑戦回数の中央値 | 3〜5回（09章 9.9-1） |
| 最初の自動化到達までの中央値 | 12分以内 |
| クリア後に前の棟へ戻ったプレイヤーの割合 | 60% 以上（未達なら継承ツリーの導線が弱い） |
| 継承ノード L1 を1つ以上購入した割合 | 50% 以上 |
