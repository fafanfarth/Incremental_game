# 09. タイムアタックモードとランキング

## 9.1 位置づけ

ストーリーモードは「どこまで数字を伸ばせるか」のゲームである。
タイムアタック（TA）は **「どれだけ速く 100万 に届かせるか」** の、完全に別の競技にする。

| | ストーリーモード | タイムアタック |
|---|---|---|
| 目的 | 数字を伸ばす・周回する | タイムを縮める |
| 永久スキル（08章） | 有効 | **全て無効** |
| 課金・広告ブースト（10章） | 有効 | **全て無効** |
| オフライン進行 | 有効 | **無効**（アプリを閉じると一時停止） |
| セーブ | 共有の1スロット | TA専用スロット（ストーリーに影響しない） |
| 解放 | 最初から | 永久スキル P-E3「賭けの記録」（1章）で解放 |

**この「全て無効」がTAの設計の核**である。
課金でも周回数でもなく、**その場の腕と知識だけで順位が決まる**。
だからこそ、ストーリー側では遠慮なく課金・広告・永久スキルを入れられる（10章）。

## 9.2 部門

| 部門 | 計測範囲 | 想定世界記録 | 備考 |
|---|---|---|---|
| **単棟TA ×5** | その棟の開始 → 【賄賂】購入 | 棟1: 約 6分 / 棟5: 約 15分 | 棟ごとに独立したランキング |
| **フルラン** | 棟1開始 → 棟5【賄賂】購入 | 約 50分 | 本命部門 |
| **週替わりチャレンジ** | 週ごとに指定 | ― | 毎週月曜 00:00 JST に更新 |

### 週替わりチャレンジの例

| 型 | 内容 |
|---|---|
| シード固定 | 全プレイヤーが同じ乱数列。運の要素が消え、純粋な最適化競技になる |
| 縛り | 「自動化スキル購入禁止」「手動タップ禁止（放置のみ）」など |
| 変則目標 | 「30分で稼げた額」を競う（タイムではなくスコア） |
| 単棟指定 | 「今週は医務棟。盤面拡張なしでR10到達」 |

縛り系の週は **既存の最適解が丸ごと無効になる** ため、
ランキング上位が毎週入れ替わる。長期的な話題性の源にする。

## 9.3 計測ルール

| ID | ルール |
|---|---|
| TA-01 | 計測はゲーム内経過時間。**端末時刻を一切参照しない**（単調増加時計のみ） |
| TA-02 | アプリを閉じる／バックグラウンドに回すと **計測とシミュレーションの両方が停止**する |
| TA-03 | ポーズ可能。ポーズ中は時間が進まず、盤面の操作もできない |
| TA-04 | 途中リセット（リトライ）は無制限。記録は「完走したラン」のみ提出される |
| TA-05 | 演出速度は全員固定（永久スキル P-E1「早送り」は無効）。ただし個々のカットシーンはスキップ可 |
| TA-06 | 【賄賂】ノードを購入した瞬間にタイマーが止まる |
| TA-07 | 乱数はラン開始時に確定するシードから決定論的に生成する |

## 9.4 不正対策（この機能の本体）

放置ゲームのランキングは **クライアント側で数値を書き換えるだけで壊れる**。
サーバが信じられるのは「入力」だけなので、次の構成にする。

### リプレイ検証方式

```
クライアント                            サーバ
  ラン開始
   └ シード s を受領 ──────────────────▶ シード s を発行し記録
  プレイ（入力を全記録）
   └ 入力ログ = [(経過ms, 種別, 座標/値), …]
  完走
   └ 入力ログ + シード + 申告タイム ────▶ 同じ決定論的シミュレータで再実行
                                          ├ 再現タイム == 申告タイム → 受理
                                          └ 不一致 → 却下
```

| ID | 要件 |
|---|---|
| TA-10 | ゲームロジックは **完全に決定論的**であること。同じシードと同じ入力列から必ず同じ結果になる |
| TA-11 | 浮動小数点の誤差で結果が変わってはならない。**固定小数点、または整数演算**で実装する |
| TA-12 | フレームレート非依存。シミュレーションは固定タイムステップ（例 60Hz）で進める。描画は分離する |
| TA-13 | 入力ログはランごとに保存し、完走時にサーバへ送信する（フルラン50分で概ね 200KB 以下に収める） |
| TA-14 | **上位100位は全て自動再検証**する。不一致・検証不能なランは掲載しない |
| TA-15 | 100位以下は抜き取り検証（10%）＋異常値検知（理論最速を下回るタイムは即却下） |
| TA-16 | 検証に使うシミュレータは **クライアントと同一のコード**（共有ライブラリ / WASM）とする |
| TA-17 | 同一アカウントの多重投稿は最良記録のみ保持。端末をまたぐ場合はアカウント単位で集約 |

### TA-11・TA-12 の重みについて

これは **エンジン選定に先行する要件** である。
ゲームロジックを描画から完全に分離し、整数演算で書いておかないと、
後からTAを足すことは事実上できない。

> **したがって、TA をやるなら Phase 0（数値プロトタイプ）の時点で
> 決定論的シミュレータとして設計しておく必要がある。**
> ここを後回しにすると、TAはリリース後に追加できない機能になる。

## 9.5 ランキング

### 構成

| 種類 | 内容 |
|---|---|
| グローバル | 全世界の上位1,000位。以下は「あなたの順位 / 全体人数」で表示 |
| 国別 | 端末ロケール由来の国コード別 |
| フレンド | Game Center / Google Play Games の友達のみ |
| 自己記録 | 自分の全ランの履歴（ベスト・平均・直近10本） |

### シーズン

- **週次シーズン**（月曜 00:00 JST 更新）で、週替わりチャレンジと単棟TAをリセット
- **フルランは通算ランキング**（リセットしない）＝ 歴代最速を残す
- シーズン終了時に上位者へ称号を付与（ゲーム内表示のみ。ゲーム性には影響しない）

### 表示内容（1行あたり）

```
 12位  ▲3   HANZO           47:12.38   棟5: 14:02   [▶リプレイ]
```

| 項目 | 内容 |
|---|---|
| 順位 / 前週比 | 前週からの変動 |
| プレイヤー名 | 端末で設定。不適切語フィルタを通す |
| タイム | ミリ秒まで |
| 内訳 | 棟ごとのラップタイム（フルランのみ） |
| リプレイ | **入力ログから再生できる**（TA-10 の決定論性がそのまま活きる） |

### リプレイ視聴の価値

不正対策のために入力ログを持つのだから、それを再生機能として見せる。

- 上位プレイヤーの手順をそのまま学習できる ＝ **攻略情報がゲーム内で完結する**
- 「自分のリプレイと1位のリプレイを並べて再生」で、どこで差が付いたかが分かる
- リプレイの保存・共有は 10章のシーズンパスの特典にする

## 9.6 ランキングに関する要件

| ID | 要件 | 優先度 |
|---|---|---|
| FR-50 | TAモードはストーリーモードと独立したセーブスロットを持つ | 必須 |
| FR-51 | TAモードでは永久スキル・IAP・広告リワードの全効果を無効化する | 必須 |
| FR-52 | TAは単棟5部門 + フルラン + 週替わりチャレンジで構成する | 必須 |
| FR-53 | ゲームロジックは決定論的で、シードと入力列から結果が一意に決まる | 必須 |
| FR-54 | ランは入力ログとして記録され、完走時にサーバで再シミュレーション検証される | 必須 |
| FR-55 | 上位100位は全件自動検証し、不一致は掲載しない | 必須 |
| FR-56 | グローバル / 国別 / フレンド / 自己記録の4種のランキングを提供する | 推奨 |
| FR-57 | 週次シーズンを持ち、フルランのみ通算ランキングとする | 推奨 |
| FR-58 | 任意のランをリプレイ再生できる | 推奨 |
| FR-59 | オフラインでもTAはプレイできる。記録は次回接続時に提出する | 推奨 |

| ID | 非機能要件 |
|---|---|
| NFR-30 | シミュレーションは固定タイムステップ（60Hz）。描画レートと完全に分離する |
| NFR-31 | すべてのゲーム内数値は整数または固定小数点。浮動小数点を状態に持たない |
| NFR-32 | 入力ログは1ラン 200KB 以下。送信は gzip 圧縮 |
| NFR-33 | ランキングAPIの応答は 500ms 以内。オフライン時はキャッシュを表示する |
| NFR-34 | サーバ側検証は1ランあたり 2秒以内（実時間50分のランを実時間2秒で再実行できる速度） |

## 9.7 スコープ上の注意

TAとランキングは **サーバ実装を伴う唯一の機能** であり、
本作で最もコストが高い部分になる（07章）。

段階的に出す:

| 段階 | 内容 | 必要なもの |
|---|---|---|
| 1 | **自己ベストのみ**（ローカル） | サーバ不要。決定論的シミュレータだけ |
| 2 | フレンドランキング | Game Center / Google Play Games のリーダーボードに乗せる |
| 3 | グローバルランキング + 検証 | 自前サーバ、リプレイ検証基盤 |
| 4 | 週替わりチャレンジ + リプレイ視聴 | 配信基盤、シーズン管理 |

**段階1だけでも「自己ベスト更新」という遊びは成立する。**
段階3以降は、ストーリーモードの評判を見てから判断してよい。
ただし段階1の時点で NFR-30 / NFR-31 を守っておくこと。そこだけは後戻りできない。
