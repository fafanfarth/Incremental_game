# Phase 0 — 数値プロトタイプ

ステージ1「独房棟」の経済を、UI なしで回して成長曲線を測るためのもの。
目的は遊ぶことではなく、**設計書の数値が本当に 25分で着地するかを確かめること**。

## 構成

| ファイル | 役割 |
|---|---|
| `data/stage01.json` | ステージ1の全数値。**バランス調整はこのファイルの編集だけで完結する** |
| `sim.py` | ゲームロジック本体。固定60Hz・描画なし・決定論的 |
| `run_balance.py` | プロファイル別の計測と、Phase 0 の合格判定 |

`sim.py` は表示を一切持たない。これは docs/09 NFR-30（制限時間や
オフライン進行がフレームレートに依存してはならない）を最初から守るための構造で、
Phase 1 以降でエンジンに載せるときも、この層はそのまま移植できる形にしてある。

## 使い方

```bash
python3 prototype/run_balance.py             # 合格判定つきレポート
python3 prototype/run_balance.py --curve     # 成長曲線を 05章 5.2 と並べる
python3 prototype/run_balance.py --seeds 20  # 試行数を増やす
```

終了コードは合格なら 0、不合格なら 1。CI に載せればバランスの回帰検知になる。

## プレイヤープロファイル

実在のプレイヤーではなく、**振る舞いを固定した3種類の仮想プレイヤー**で測る。

| 名前 | タップ/秒 | 想定 |
|---|---|---|
| 手動 | 4.0 | 画面を見て遊んでいる。両親指で持続可能な速度 |
| 併用 | 1.2 | ときどき触る |
| 放置のみ | 0.1 | ほぼ触らない。自動収入で進む |

購入方針は共通で **「今払えるもののうち、最も回収の速いものを1つ買う」**。
賄賂だけは払えるようになった時点で最優先で買う。

> これは最速クリアを狙う打ち方ではない。人間の上手いプレイはこれより速くなる。
> あくまで **バランスの回帰を検出するための固定された物差し** として使う。

## 合格条件（docs/07 Phase 0）

- 手動プレイで **25分 ±5**
- 放置のみで **60分 ±15**

現在の `data/stage01.json` での実測は [docs/11-phase0-findings.md](../docs/11-phase0-findings.md) を参照。

## 注意

- 乱数は seed 固定。同じ seed と同じ JSON からは必ず同じ結果になる
- スキル効果は JSON の `effects` で表現する。新しい効果を足すときは
  `sim.py` の `_effects` 系に型を1つ増やす
- 収入に直結しないスキル（検査対策など）は購入方針が無視してしまうため、
  最低限の評価値を与えて死に枝にしない処理を入れてある（`_simulated_gain`）
