# Phase 0 — 数値プロトタイプ

全5ステージの経済を、UI なしで回して成長曲線を測るためのもの。
目的は遊ぶことではなく、**設計書の数値が本当に目標時間で着地するかを確かめること**。

## 構成

| ファイル | 役割 |
|---|---|
| `data/stage01〜05.json` | 各ステージの全数値。**バランス調整はこのファイルの編集だけで完結する** |
| `sim.py` | 共通エンジン。通貨・スキル・購入方針・抜き打ち検査・賄賂。固定60Hz・描画なし・決定論的 |
| `cores.py` | ステージ固有の稼ぎ方。各ステージで最も壊れやすい部分を再現する |
| `run_balance.py` | プロファイル別の計測と合格判定 |
| `tune.py` | 倍率スタックを減衰させて目標時間に寄せる二分探索 |

`sim.py` と `cores.py` は表示を一切持たない。これは docs/09 NFR-30（制限時間や
オフライン進行がフレームレートに依存してはならない）を最初から守るための構造で、
Phase 1 以降でエンジンに載せるときも、この層はそのまま移植できる形にしてある。

## 使い方

```bash
python3 prototype/run_balance.py             # 全5ステージの合格判定
python3 prototype/run_balance.py --stage 3   # 1ステージだけ
python3 prototype/run_balance.py --curve 1   # 成長曲線
python3 prototype/run_balance.py --seeds 8   # 試行数を増やす
python3 prototype/tune.py                    # 目標時間に寄せる減衰係数を探索
```

終了コードは合格なら 0、不合格なら 1。CI に載せればバランスの回帰検知になる。

## プレイヤープロファイル

実在のプレイヤーではなく、**振る舞いを固定した3種類の仮想プレイヤー**で測る。

| 名前 | タップ/秒 | 想定 |
|---|---|---|
| 手動 | 4.0 | 画面を見て遊んでいる。両親指で持続可能な速度 |
| 放置のみ | 0.1 | ほぼ触らない。自動収入で進む |

購入方針は共通で **「今払えるもののうち、最も回収の速いものを1つ買う」**。
賄賂だけは払えるようになった時点で最優先で買う。

> これは最速クリアを狙う打ち方ではない。人間の上手いプレイはこれより速くなる。
> あくまで **バランスの回帰を検出するための固定された物差し** として使う。

## 合格条件

1. **手動クリアが docs/05 5.3 の目標時間 ±20% に入る**
2. **放置のみ ÷ 手動 の比が 1.5〜4.0 に入る**
   （1.5 未満＝触る意味がない／4.0 超＝放置が苦行）

実測値と、そこから必要になった設計変更は
[docs/11-phase0-findings.md](../docs/11-phase0-findings.md) を参照。

## 注意

- 乱数は seed 固定。同じ seed と同じ JSON からは必ず同じ結果になる
- スキル効果は JSON の `effects` で表現する。新しい効果を足すときは
  該当ステージのコア（`cores.py`）が読む型を1つ増やす
- 収入に直結しないスキル（検査対策など）は購入方針が無視してしまうため、
  最低限の評価値を与えて死に枝にしない処理を入れてある（`_simulated_gain`）
